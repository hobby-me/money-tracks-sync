# synk-tui — консоль оператора

Терминальный интерфейс в духе k9s для управления сервером синхронизации
Money Tracks: учётки, устройства, коды приглашений, состояние сервера.
Всё, что умеют команды `synk account|invite|device|status`, но глазами и
клавишами. Эта же страница на сервере: `man /opt/synk/synk-tui.1`.

## Запуск

| Где | Как |
|---|---|
| На сервере | `/opt/synk/synk-tui` — читает `/opt/synk/synk.env`, стартует от пользователя `synk` |
| С мака | `make tui` — ssh на сервер и сразу консоль |
| Локально, на тестовых данных | `make run-tui` — временная папка, две учётки, устройства, висящий код |
| Вручную | `synk tui --data DIR [--listen ADDR] [--url URL]` или `synk --data DIR --tui` |

Консоль работает параллельно с сервисом: обе стороны ходят в SQLite в
WAL-режиме с `busy_timeout`.

## Экран

```

┌─ accounts[2] ─────────────────────────────────────────────────────────────────┐
│ ID     NAME    CREATED     DEVICES       INVITES  OPS  ROWS  PHOTOS  SIZE  LAST SYNC
│ 01M1…  Alex  2026-09-01  1 +1 revoked        —  1 234  456     12  3.2M        5m
│ 01M2…  Family  2026-09-20  1                   1      —    —      —     —         —
└───────────────────────────────────────────────────────────────────────────────┘
 synk  accounts                                                   обновлено 12:03:15
```

- **Шапка.** Слева: версия и папка данных; адрес сервера и состояние по
  `/healthz` (`● up` с версией из `/metrics` или `● down` с причиной);
  счётчики push/pull/photos, при наличии errors; итоги по учёткам,
  устройствам, действующим кодам. Правее — колонки хоткеев: навигация,
  действия текущей вкладки, общие. В узком терминале колонки скрываются
  справа налево.
- **Таблица.** Заголовок `devices(Alex)[2] /pix`: вкладка, учётка-фильтр,
  число строк, активный фильтр. Курсор — подсвеченная строка. Отозванные
  устройства и неактуальные коды — серым.
- **Нижняя строка.** Крошки пути слева; справа — результат последнего
  действия (зелёный), ошибка (красный) или время обновления. В режиме
  команды или фильтра строка целиком отдаётся вводу и подсвечивается.

Данные перечитываются каждые 5 секунд, `r` — сейчас.

## Вкладки

**1 · учётки.** id, имя, создана, устройства (активные `+N revoked`),
действующие коды, ops (`latest_seq`), rows (записей LWW-состояния), фото,
размер (sync.db + фото), давность последнего пуша.

**2 · устройства.** id, учётка, имя, состояние (active/revoked), роль
(admin), сколько правок прислало и когда последнюю, дата подключения.
`enter` на учётке во вкладке 1 показывает устройства только этой учётки
(заголовок `devices(Имя)`), `esc` возвращает.

**3 · коды приглашений.** хэш (самого кода в базе нет), учётка, роль,
состояние (pending/used/expired), срок (для действующих — обратный
отсчёт), когда погашен. Учётка-фильтр действует и здесь.

**4 · дашборд.** Три панели: **диск** (данные synk, учётки, trash;
занято/всего/свободно с полосой; доля synk на диске), **сервер** (up/down,
версия, uptime, RSS, RPS, всего запросов, 4xx/5xx, внутренние ошибки,
push/pull/photos, адреса API и метрик), **застой учёток** (живые, молчат
1 мес+, 6 мес+, 1 год+). Ниже — запросы по устройствам: rps за последние
5 с, всего, 5xx; строка «без авторизации» — register и битые токены. Внизу
таблица учёток по застою, самые тихие сверху; IDLE подсвечен (жёлтый 1m+,
оранжевый 6m+, красный 1y+; `∅` — ни одного пуша, считается от создания).
Всё это те же серии, что отдаёт порт метрик для будущего Prometheus.

## Клавиши

### Навигация

| Клавиша | Действие |
|---|---|
| `↑` `↓` `j` `k` | по строкам |
| `pgup` `pgdn` `ctrl+u` `ctrl+d` | страницами |
| `g` `home` / `G` `end` | начало / конец |
| `1` `2` `3` `4` | вкладки |
| `enter` | в учётках — устройства учётки; в устройствах — детали |
| `esc` | сбросить фильтр → выйти из учётки → (в учётках) ничего |
| `/` | фильтр подстрокой по всем колонкам; `enter` оставить, `esc` сбросить |
| `r` | перечитать сейчас |
| `?` | помощь |
| `q` `ctrl+c` | выход |

### Действия

| Клавиша | Действие |
|---|---|
| `a` | новая учётка: имя → создать → предложит сразу выпустить админ-код первого устройства |
| `i` | код приглашения для учётки выбранной строки; спросит роль — обычное устройство или администратор (заводит учётки, приглашает в чужие — для своего телефона) |
| `x` | в устройствах — отозвать токен (данные целы, устройство перестаёт синхронизироваться до нового кода); в кодах — отменить действующий код |
| `m` | снять админство с устройства |
| `d` | детали: учётка — instance_id, latest_seq, последний push, rows по сущностям, фото, размер; устройство — id, учётка, состояние, роль, даты, активность |
| `p` | (коды) удалить погашенные и протухшие коды старше суток |
| `D` | (учётки, дашборд) удалить учётку, молчавшую год: подтверждение вводом имени, устройства и коды удаляются, папка `acc/<id>` переезжает в `data/trash/<id>-<дата>`; активную учётку консоль не удалит — только `synk account delete --force` |
| `t` | (дашборд) очистить trash окончательно |

Каждое изменяющее действие спрашивает подтверждение: `y`/`enter` — да,
`n`/`esc` — нет, `tab`/стрелки переключают кнопку. Опасные (отзыв,
отмена) — с красной рамкой. В списках выбор цифрой или `enter`.

## Команды `:`

Двоеточие открывает командную строку внизу. Ссылка на учётку — id или имя
без учёта регистра; неоднозначное имя консоль отклонит и попросит id.

```
:accounts  :acc  :a              вкладка учёток
:devices [учётка]  :dev  :d      устройства (всех или одной)
:invites [учётка]  :inv  :i      коды (всех или одной)
:invite <учётка> [admin]         выпустить код и сразу показать сообщение
:add <имя учётки>                новая учётка
:purge                           чистка старых кодов
:delete <учётка>                 удалить молчавшую год учётку (с подтверждением)
:dash  :o                        дашборд
:help  :?                        помощь
:q  :quit                        выход
```

## Код приглашения

После выпуска кода консоль показывает окно без боковых рамок, прижатое к
левому краю, чтобы выделение мышью давало ровно текст сообщения:

```
Money Tracks — подключение устройства
Сервер:  https://sync.example.com
Учётка:  Alex
Код:     AZ0DFD0K9HJ8X2S4
Роль:    администратор
Код одноразовый, действует до 12:34 (+05), около 10 минут.
В приложении: Настройки → Синхронизация → Подключить устройство.
```

Над блоком — код крупно и живой обратный отсчёт. Адрес сервера берётся из
`SYNK_PUBLIC_URL` (`/opt/synk/synk.env`) или `--url`. Тот же блок печатает
`synk invite` в CLI.

## Сценарии

- **Подключить свой новый телефон к учётке Alex.** `1` → строка Alex →
  `i` → `2` (администратор) → скопировать блок → ввести код в приложении.
  Через несколько секунд устройство появится во вкладке `2`, в шапке
  вырастет push.
- **Дать доступ к учётке члену семьи.** `1` → строка учётки → `i` → `1`
  (обычное устройство) → отправить блок.
- **Потерян телефон.** `2` → `/` iphone → `x` → подтвердить. Если это было
  админ-устройство — `i` → администратор для другого.
- **Код выпустили, но передумали.** `3` → строка pending → `x`.
- **Новая учётка.** `a` → имя → `enter` → «Выпустить» — сразу админ-код.
- **Кончается место / кто грузит сервер.** `4`: полоса диска и доля synk;
  запросы по устройствам — кто шлёт больше всех и у кого 5xx.
- **Убрать мёртвые учётки.** `4`: панель застоя и таблица с красным `1y+`
  сверху → `D` → набрать имя → учётка в trash. Потом `t` очищает trash.
- **Проверить, что сервер живёт.** Шапка: `● up` и версия; счётчики
  растут; во вкладке `1` колонка LAST SYNC; `d` на учётке — `latest_seq` и
  `instance_id`, которые клиент показывает в диагностике.

## Окружение

- `/opt/synk/synk.env` — `SYNK_DATA`, `SYNK_LISTEN`, `SYNK_METRICS_LISTEN`,
  `SYNK_PUBLIC_URL`; пишется ансиблом, читают systemd-юнит, `synk-tui` и CLI.
- Метрики — отдельный порт `127.0.0.1:8091`, nginx его не проксирует:
  через домен статистика недостижима. Консоль и `synk status` читают его
  с localhost; будущий Prometheus снимет тот же порт без изменений в synk.
- Цвета — ANSI-256, без truecolor; `NO_COLOR` отключает.
- Минимальная разумная ширина — 80 колонок.

## Устройство

Консоль — тонкий слой над `internal/admin`, тем же пакетом, что использует
CLI. Каждая клавиша вызывает ту же функцию, что соответствующая команда:
`x` = `synk device revoke`, `i` = `synk invite`, `a` = `synk account add`.
Новая операция добавляется в `internal/admin` один раз и выводится в CLI
строкой (`cmd/synk`) и в TUI клавишей (`internal/tui/model.go`).

```
cmd/synk/main.go         флаги → admin → строки
internal/tui/model.go    клавиши, :-команды, сценарии → admin
internal/tui/view.go     шапка, рамка таблицы, нижняя строка
internal/tui/table.go    таблица с автошириной колонок
internal/tui/overlay.go  модалки: подтверждение, ввод, выбор, уведомление
internal/admin           операции, статистика, Probe сервера, InviteText
```
